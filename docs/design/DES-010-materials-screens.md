## 目的・背景

4a〜4c で、素材集の申請・機械審査・承認・公開・毎日の確認が API と Lambda でできるようになった（開発用で通しの確認済み）。本書は、それを制作元と運用者が画面から使えるようにする。API-001 1.1 の操作をそのまま使い、API は変えない。

## 方針・決定事項

| No. | 判断 | 理由 |
|---|---|---|
| N-1 | **制作元の画面は、配信元の画面に「素材集」のメニューを足す**（アカウントは共通、M-16）。制作元の役割がないアカウントには、「素材集」を開くと説明と「制作元として始める」のボタンを出す（`POST /api/publisher/roles/producer`） | 別の画面にすると、鍵や設定が 2 か所になる |
| N-2 | 素材集の画面: 一覧と登録、詳細（状態、公開中の版の要約、毎日の確認の不具合、使っているチャンネル、申請の一覧）、申請（ZIP を選ぶ → ブラウザで署名 → アップロード → 機械審査の結果を待って表示）、取り消し。機械審査の結果は `errors`・`external`（外部の素材ごと）・`inUse`（D-8）・`warnings`（利用許諾の縮小）を分けて出す | API-001 C-18・C-19 |
| N-3 | **素材集の署名はブラウザで行う**。今の `signPackage`（チャンネル）と同じく、鍵のファイルを合言葉で開き、`collection-package` の `signature.json` を作る。署名の前に `collection.json` の `id`・`version`・`producer` を確かめる | チャンネルと同じ。秘密鍵をサーバーに送らない（DES-003） |
| N-4 | **運用者の素材集の審査の画面**（`/review/collections/:collectionId/:submissionId`）: パッケージをブラウザで開き、素材ごとに中身を出す（テキストは本文、画像は表示、外部の音声・映像は `<audio>`・`<video>` で元の URL を再生）。題材（`about`）は位置を OpenStreetMap へのリンクで出す（地図は埋め込まない）。タグ・利用許諾・出典・書き起こしも並べる。審査待ちの一覧の素材集の行から開く | 審査基準の素材の項目（出典・写っているもの・書き起こし・地点の安全）を画面で確かめられるようにする。地図のライブラリは足さない（API-001 未決事項 No.5 は「リンク」で解決） |
| N-5 | 身元の確認（C-17）: 審査の画面で、アカウントが確認済みでなければ、承認の欄に「確認の方法」「確認した内容」を必須で出し、アカウントの表示名・連絡先を並べる。確認済みなら、記録（方法・日時）を出す | D-20 |
| N-6 | 運用者の素材集の管理: 配信元（アカウント）の詳細に「素材集」の欄を足し、素材集の詳細（使っているチャンネル・毎日の確認の不具合・取り下げ）へ進める。取り下げはチャンネルと同じ欄（理由・重さ・版） | 運用者向けの素材集の一覧の API はないので、アカウントから辿る |
| N-7 | チャンネルの画面（配信元・運用者）に、機械審査の `collections`（宣言した素材集ごとの解決の結果）と、承認済みの版の `appStage`・`minAppVersion` を出す。`minAppVersion` が仮の大きな値のときは「素材に対応したアプリが出るまで、アプリの一覧に出ません」と添える | 配信元が、なぜアプリに出ないかを分かるようにする（DES-007 J-9） |
| N-8 | 基準（`selectors`）が今どの素材集に当たるかの表示（API-001 未決事項 No.6）は、今回は入れない | 当たりの判定（タグ・地域・利用許諾・順番）を画面で組み立て直すことになる。アプリの段（SanpoGuide T-8）で判定を作ってから考える |
| N-9 | 利用ガイド: `docs/guide/producer.md`（素材集の作り方: `collection.json` の書き方、外部の素材の置き方、署名と申請、使っているチャンネル、毎日の確認）を足し、`concepts.md` の図に素材集を足す | 配信元向けのガイドと同じ扱い |

## 検証の計画

| 項目 | 内容 |
|---|---|
| 単体テスト | `publisher-crypto` の素材集の署名（`collection-package` の形、`id`・`version`・`producer` の確かめ、station-format と同じ署名の形になること）。型検査と既存のテスト |
| 開発用での確認 | 配備して、開発者が画面で確かめる（DES-002・DES-003 と同じ）: 制作元として始める → 素材集の登録 → ZIP の署名と申請 → 機械審査の結果 → 運用者の審査（素材の表示・身元の確認）→ 承認 → 使っているチャンネル。チャンネルの画面の `collections` の表示 |

## 検証結果

| 項目 | 結果 |
|---|---|
| 単体テスト | 素材集の署名 2 件（`collection-package` の形が station-format の読む形と一致し署名が検証できる、ID・制作元・`collection.json` の確かめ）。チャンネルの署名は共通化したあとも今のテストがそのまま合格。全体で 135 件・型検査・SPA のビルドが合格 |
| 契約との差 | チャンネルの `latestApproved` に 4b-2 から `appStage` などが入っているが、OpenAPI の `LatestApproved` にはない（API は知らない項目を返してよい）。画面では型を広げて読んでいる。次に API-001 を改訂するときに足す |

## 未決事項・リスク

| No. | 内容 | 対応 |
|---|---|---|
| 1 | 外部の素材を審査の画面で再生すると、運用者のブラウザが制作元のサーバーに直接つながる | 運用者だけの操作で、利用者の位置は関係しない。気になる場合は、再生の前に「外部のサーバーにつながります」と出す |
| 2 | 制作元が `collection.json` を手で書くのは難しい | ガイドに見本を載せる。作成を手伝う道具は、要望が出たら考える |
