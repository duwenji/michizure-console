## 目的・背景

[DES-007](DES-007-materials-review.md)（4a）で、機械審査が素材集とチャンネルの素材を確かめ、承認のときに写す値（`listing`）を申請に記録するようになった。本書は、[API-001](../console-api.md) 1.1 の残り（制作元と運用者の操作）と、[DM-001](../data-model.md) 1.3 の書き込み（利用の記録・退会・移し替え）を実装する方式を決める。

## 実装の分け方

| PR | 内容 |
|---|---|
| 4b-1 | 制作元の役割、素材集の登録・申請・取り消し・一覧・使っているチャンネル、運用者の素材集の審査（開始・戻す・承認・差し戻し・却下・パッケージ・記録）・取り下げ・アカウントの素材集、上限と使用量、型の生成し直しと既存コードの直し |
| 4b-2 | チャンネルの承認での利用の記録と、素材集の確かめ直し、チャンネルの取り下げでの利用の記録の削除、退会・鍵の移し替えの拡張、通知（C-20）の出来事と文面 |

4b-1 だけでも、素材集を申請・審査・承認できる（リストへの掲載は 4c）。

## 方針・決定事項

| No. | 判断 | 理由 |
|---|---|---|
| K-1 | 審査の操作（開始・戻す・判定）は、チャンネルと素材集で共通の処理にし、違い（キーの接頭辞、受付・保管の S3 の接頭辞、アイコンの有無、見本の有無、承認で写すもの）を小さな「種類の記述」で渡す | 状態の移り方と同時の書き込みの守り方（M-11）を 1 か所に保つ |
| K-2 | 制作元の役割（C-15）は、アカウントの `roles` に `producer` を足すだけ（`If-Match`）。素材集の操作の入り口で、役割と `active` を確かめる共通の関数を使う（`role_required`・`publisher_not_active`）。1.2 までのアカウントは `roles` がなければ `["publisher"]` として読む | DM-001 M-16・移行メモ |
| K-3 | 素材集の承認（C-17）: アカウントに `producerVerification` がなければ、要求の `verification` を必須にし、同じトランザクションで書く。表示名の変更（`PATCH /api/publisher`）で `producerVerification` を消す | DM-001 M-17、D-20 |
| K-4 | 素材集の承認では、パッケージを公開用のバケットの `col/{sha256}.zip` に写し、申請の `listing` から `latestApproved` を作る（パッケージを開かない）。`minAppVersion` は段と版の対応表（K-6）から決める | DES-007 J-8 |
| K-5 | **D-8 の確かめ直しと同時の書き込み**: 素材集の承認は、利用の記録を読み、`listing.resourceTypes` に記録の素材の ID と種類があることを確かめ（なければ `resource_in_use`）、読んだ利用の記録の `rev` を条件に入れる。チャンネルの承認は、使う素材集の項目の `rev` を条件に入れる。どちらかが後から書くと、もう一方の条件が外れて 412 になる | DM-001 M-22 の「`rev` の条件」。チャンネルと素材集の承認が同時に来ても、参照中の素材が消えない |
| K-6 | 段と版の対応表（API-001 C-21）は環境ごとの設定（`infra/lib/config.ts` の `appStageVersions`。PR を通して変える）から環境変数 `APP_STAGE_VERSIONS`（JSON）で API の Lambda に渡す。既定は `{"0":1,"1":9999,"2":9999,"3":9999}`（段 0 は今の値） | DES-007 J-9 |
| K-7 | **チャンネルの承認での素材集の確かめ直し**（API-001 1.1）: API は station-format を持たないので、機械審査が記録した `listing.collections`・`listing.uses` と、使う素材集の今の項目（`LISTED`・`status`・`latestApproved` の版・`grants`・`resourceTypes`）で確かめる。リストに載っていない・版が `minVersion` より古い・利用許諾が外れた・参照する素材がない、のどれかなら `invalid_state`（`detail` に理由）。通れば、利用の記録を書き直す（使わなくなった素材集の記録は消す） | 機械審査から承認までの間に、素材集が取り下げ・更新されることがある |
| K-8 | 素材集の取り下げは、チャンネルと同じ形（`REVOKE#` の項目、`REVOKED` の GSI2、`kind = collection`）。利用の記録は残す（知らせの宛先のため。DM-001） | DM-001 M-25 |
| K-9 | チャンネルの取り下げで、そのチャンネルの利用の記録を消す（GSI1 `CH#{channelId}` / `USES#` で引く） | DM-001 1.3「利用の記録」 |
| K-10 | 退会（C-22）・鍵の移し替えの承認（M-25）は、今のトランザクションに素材集の分を足す。項目が 100 件を超えそうなら（上限を運用者が広げた場合）、取り下げを先に別のトランザクションで行う | DM-001「1 つのトランザクションは 100 件まで」 |
| K-11 | 通知（C-20）の出来事を足す: `collection.approved`・`collection.returned`・`collection.rejected`・`collection.revoked`（制作元へ）、`collection.updated`・`collection.revoked_used`・`collection.grants_narrowed`（使っているチャンネルの配信元へ。利用の記録から引く）。文面は今の通知と同じく、見本・運用者の ID・トークンを含めない | API-001 C-14・C-20、CV-19 |
| K-12 | `GET /api/collections/{id}/used-by` は利用の記録をそのまま返し、チャンネルの名前・配信元の表示名は、チャンネルとアカウントの項目から引いて足す（取り下げ・退会したものは名前を出さない） | API-001 C-18 |

## 検証の計画

| 項目 | 内容 |
|---|---|
| 単体テスト（DynamoDB Local、今の `api/test` と同じ） | 役割の有効化と `role_required`、素材集の登録（`collection_id_taken`、チャンネルと同じ ID は通る）・上限、申請（共通の 1 日の数・審査待ち 1 つ）、承認（身元の記録の必須と記録、`latestApproved`・`minAppVersion`・公開のバケットへのコピー）、D-8 の確かめ直しと同時の承認（K-5）、差し戻し・却下・取り下げ、審査待ちの一覧の 2 種類、表示名の変更で身元の記録が消える |
| 4b-2 の単体テスト | チャンネルの承認での利用の記録（書く・書き直す・消す）と確かめ直し（K-7）、取り下げでの削除、退会・移し替えの素材集、通知の宛先と出来事 |
| 本物の AWS での通しの確認 | 4b-1 の後: 素材集の申請 → 機械審査（外部の素材） → 承認 → 公開用のバケットの `col/`。4b-2 の後: それを使うチャンネルの申請 → 承認 → 利用の記録 |

|---|---|
